请将以下规则写入长期记忆，并在以后所有 Codex 指令生成任务中默认执行：

1. **四遍审核**：每次输出 Codex 指令前必须完整审核 4 遍，分别检查需求覆盖、逻辑一致性、权限与安全边界、执行与验收闭环；最终确保无遗漏、无重复、无冲突。

2. **输出形式**：较短的 Codex 指令直接完整放入**一个代码块**；较长的 Codex 指令生成可下载的 **`.txt` 文件**，不要在聊天中重复全文，并同时给出明确的 Codex 启动/使用指令。

3. **配置建议**：每次必须先给出：

   * 所需权限；
   * 推荐模型与推理强度；
   * 较节省额度的次优配置。

   如果使用**完全访问权限**，必须严格限制项目目录、允许修改范围、文件系统边界及禁止操作，防止越权修改或在项目外遗留文件。

4. **预期效果**：生成 Codex 指令时，必须同时说明该指令执行后预计完成什么、修改或验证什么，以及成功后项目应达到什么状态。

5. **指令质量**：Codex 指令必须精炼准确、逻辑严谨、条理清晰、考虑周全；删除重复要求，消除规则冲突，不堆砌无实际作用的说明。

6. **高效执行**：要求 Codex 尽可能执行准确、具体、最少必要的操作。优先复用已有审计和运行证据，一次性读取必要源码，执行最小授权修改，再进行集中静态/动态验证；避免重复搜索、重复读取、重复测试、大范围无目的扫描和反复执行相同命令。

总原则：

**四遍审核 → 配置建议 → 明确边界 → 精确执行 → 最小修改 → 集中验证 → 明确预期效果。**
